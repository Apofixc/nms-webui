# Начало работы (Getting Started)

## Обзор системы и назначение приложения [icon:rocket_launch]

**NMS WebUI** (*Network Management System Web Interface*) — это специализированная масштабируемая платформа для централизованного мониторинга, агрегации метрик, диагностики и оперативного управления комплексами цифрового ТВ-вещания (DVB-S/S2/T2/C), OTT/IPTV сетями и стриминговыми медиа-серверами.

### Назначение и решаемые задачи

В современных гетерогенных сетях вещания видеоконтент проходит длинный технологический тракт: от приемных спутниковых тарелок и IP-стримеров до головных станций мультиплексирования, транскодеров и CDN-серверов. Отказ любого узла или ухудшение качества связи в IP-канале приводят к рассыпанию картинки или полной потере вещания у абонентов.

NMS WebUI объединяет разрозненные элементы инфраструктуры в единый интуитивно понятный интерфейс и решает следующие задачи:

1. **Сквозная визуализация тракта вещания**: Отображение состояния медиа-потоков на всех этапах доставки — от входа с головной станции до выдачи абонентам.
2. **Мульти-инстансный мониторинг**: Одновременный сбор данных с десятков и сотен удаленных медиа-серверов (Cesbo Astra, MediaMTX и др.) через единую точку доступа.
3. **Обнаружение деградации сигнала в реальном времени**: Мгновенный фиксация ошибок непрерывности TS-пакетов (Continuity Counter Errors), просадок битрейта, межпакетного джиттера и расссинхронизации.
4. **Гибкая панель оператора (Dashboard)**: Персонализируемый рабочий стол с виджетами, поддерживающими Drag-and-Drop, масштабирование, фильтрацию и быстрые пресеты макетов.
5. **Оперативный визуальный контроль**: Встроенный медиаплеер с поддержкой HLS, RTSP и WebRTC для быстрой видеоверификации каналов прямо из браузера.
6. **Централизованный журнал алармов**: Единая лента событий и уведомлений с разграничением по уровню критичности (Critical, Warning, Info).

## Архитектура и ключевые концепции [icon:account_tree]

Платформа NMS WebUI разработана с использованием современной микросервисно-ориентированной асинхронной архитектуры. Это обеспечивает высокий уровень отказоустойчивости, низкую задержку обновления данных и возможность легкого расширения функционала через подключаемые модули.

### Ключевые компоненты платформы

#### 1. Клиентская часть (Frontend)
- **Фреймворк**: Vue 3 (Composition API, TypeScript) для реактивного управления состоянием UI.
- **Сборщик**: Vite — обеспечение мгновенной горячей перезагрузки (HMR) в разработке и оптимизированного бандла в production.
- **Стилизация**: Tailwind CSS с кастомной дизайн-системой, адаптивной темной темой и поддержкой CSS-переменных.
- **Состояние**: Pinia — централизованное хранилище состояния для настроек виджетов, списков инстансов и параметров сессии.
- **Интернационализация (i18n)**: Встроенный движок локализации (поддержка русского и английского языков).

#### 2. Серверная часть (Backend API)
- **Фреймворк**: FastAPI на базе Starlette и Pydantic v2 — высокопроизводительный асинхронный Python-бэкенд.
- **Сервер приложений**: Uvicorn — асинхронный ASGI-сервер.
- **Модульная структура (`backend/modules/`)**:
  - `stream`: Модуль управления и диагностики медиа-потоков.
  - `system`: Модуль системных настроек, журналов и управления вики-документацией.
  - `nodes`: Модуль интеграции с головными станциями (Astra API adapter).
  - `analytics`: Модуль агрегации временных рядов метрик битрейта и ошибок.
- **Асинхронность**: Все обращения к внешним инстансам и БД выполняются через `async/await` без блокировки главного потока.

#### 3. Хранение данных и конфигурация
- **`instances.yaml`**: Декларативный конфигурационный файл, содержащий список всех мониторируемых серверов вещания, их IP-адреса, порты и ключи доступа API.
- **`nms.db` (SQLite)**: Легковесная реляционная база данных для хранения учетных записей, ролей пользователей, системных логов и сохранений пользовательских макетов дашборда.

## Глоссарий терминов [icon:menu_book]

Для удобства навигации по системе ниже приведен расширенный справочник терминов, используемых в интерфейсе и документации NMS WebUI:

### Сетевые термины и протоколы
- **NMS (Network Management System)** — система управления и мониторинга сетевыми элементами и инфраструктурой вещания.
- **IPTV (Internet Protocol Television)** — технология передачи цифрового телевизионного сигнала по IP-сетям с использованием протоколов Multicast/Unicast.
- **OTT (Over-the-Top)** — метод доставки видеоконтента через публичный Интернет по протоколам HLS/DASH без гарантированного QoS.
- **SRT (Secure Reliable Transport)** — открытый видеопротокол с низкой задержкой и стойкостью к потерям пакетов в нестабильных сетях.
- **RTSP (Real Time Streaming Protocol)** — прикладной протокол для управления трансляцией потокового видео в реальном времени.
- **UDP Multicast** — режим групповой адресации в IP-сетях, используемый для эффективности передачи одного видеопотока множеству приемников.

### Метрики качества и телеметрия
- **Bitrate (Битрейт)** — объем данных видеопотока, передаваемый за одну секунду. Измеряется в `Кбит/с` (Kbps) или `Мбит/с` (Mbps).
- **CC Error (Continuity Counter Error)** — ошибка счетчика последовательности пакетов MPEG-TS. Возникает при потере IP-пакетов в сети или сбоях приемного оборудования.
- **Jitter (Джиттер)** — отклонение от нормы времени прихода IP-пакетов. Высокий джиттер приводит к опустошению буфера плеера.
- **SNR (Signal-to-Noise Ratio)** — отношение сигнал/шум в приемном тракте DVB-тюнера (измеряется в дБ).
- **BER (Bit Error Rate)** — коэффициент битовых ошибок до (Pre-BER) и после (Post-BER) декодера FEC.

### Концепции NMS WebUI
- **Instance (Инстанс)** — подключенный к NMS медиа-сервер (например, Cesbo Astra или MediaMTX), с которого собираются метрики.
- **Widget (Виджет)** — интерактивный графический компонент на дашборде (график битрейта, плеер, индикатор статуса, список алармов).
- **Preset (Пресет)** — сохраненный профиль расположения виджетов и их настроек, который можно мгновенно применить на рабочем столе.
- **Slot (Слот)** — ячейка сетки на рабочем столе дашборда, в которую монтируется виджет.
- **SSE (Server-Sent Events)** — протокол постоянного однонаправленного соединения бэкенда с фронтендом для доставки обновлений метрик в реальном времени.
