# 🛡 Журнал аудита безопасности (Security Audit Log)

---

## 📌 1. Назначение страницы, URL-маршруты и RBAC-права

**Журнал аудита безопасности** является центральным элементом системы подконтрольности NMS WebUI. Он обеспечивает гарантированную регистрацию всех критических действий операторов и администраторов, включая входы в систему, сбои аутентификации, изменения прав, блокировки пользователей, операции с модулями и восстановление системы.

* **URL-маршрут**: `/settings/system` (вкладка *Аудит безопасности*)
* **Требуемые права доступа (RBAC)**: `system.admin` или `audit.view`.

---

## 🖥 2. Подробный функциональный состав

### 2.1. Панель поиска и фильтрации аудита
Для быстрого расследования инцидентов безопасности панель фильтров содержит:

1. **Выбор диапазона дат (`Date Range Picker`)**:
   * Фильтрация событий за выбранный период (например, *«За последние 24 часа»*, *«За неделю»* или пользовательский интервал).

2. **Категории событий (`Category Filter`)**:
   * `Аутентификация` — Входы, выходы, сбои ввода пароля, запросы 2FA.
   * `Управление пользователями` — Создание, блокировка, сброс паролей пользователей.
   * `Роли и права (RBAC)` — Создание ролей, смена матрицы разрешений.
   * `Модули` — Установка, включение, отключение и удаление плагинов.
   * `Системные настройки` — Бэкапы, восстановление, смена сетевых настроек.

3. **Поиск по оператору и IP-адресу**:
   * Фильтрация по логину учетной записи или IP-адресу инициатора действия.

4. **Статус выполнения (`Status Filter`)**:
   * `Успешно (Success)` — Зеленый бейдж.
   * `Отказ в доступе (Denied)` — Желтый бейдж.
   * `Ошибка (Failure)` — Красный бейдж.

---

### 2.2. Таблица событий аудита (Audit Events Table)
* **Колонки таблицы**:
  * **Время**: Дата и время события с точностью до миллисекунд.
  * **Оператор**: Логин пользователя и его роль на момент действия.
  * **Категория и Действие**: Системный код операции (например, `USER_LOCKED`, `ROLE_PERMISSIONS_UPDATED`).
  * **IP-адрес**: IPv4/IPv6 адрес клиента.
  * **Статус**: Результат выполнения операции.
  * **Детали (`visibility`)**: Кнопка вызова подробной инспекции записи.

---

### 2.3. Модальное окно инспекции детализации (Event Details Modal)
Просмотр подробной информации о выбранном событии:

* **Инспекция изменений (Diff Mode)**:
  * Показывает состояние объекта **«До изменения»** (`Before State`) и **«После изменения»** (`After State`) в формате JSON.
* **Контекст запроса**:
  * Вызванный API-эндпоинт (`POST /api/v1/users/4/lock`), HTTP-метод, User-Agent браузера и идентификатор сессии.

---

### 2.4. Гарантия неизменяемости (Immutability)
* Записи аудита защищены от редактирования и удаления через интерфейс WebUI.
* Пользователям отображается информационное уведомление о неизменяемости логов безопасности.

## 🔄 3. Взаимодействие с остальным приложением

```mermaid
graph TD
    AppControllers[Все сервисы NMS WebUI] -->|Вызов audit.py| AuditModule[Backend: core/audit.py]
    AuditModule -->|Запись события| DB[(SQLite: nms.db - audit_logs)]
    UI[Frontend: SecurityAuditLog View] -->|REST API GET| API[/api/v1/audit/logs]
    API -->|Чтение событий| DB
    UI -->|Экспорт| CSV_JSON[Файлы CSV / JSON]
```

### 3.1. Backend REST API
* `GET /api/v1/audit/logs`: Загрузка списка событий с фильтрацией, сортировкой и пагинацией.
* `GET /api/v1/audit/categories`: Получение реестра категорий действий.
* `GET /api/v1/audit/export`: Экспорт аудита в файлы `.csv` и `.json`.

### 3.2. Перехват событий (`audit.py`)
* Подсистема `backend/core/audit.py` встроена во все ключевые сервисы приложения.
* При вызове функций изменения состояния (например, `update_user_role`) декоратор автоматически записывает параметры вызова в таблицу `audit_logs`.

### 3.3. База данных `nms.db`
* Таблица `audit_logs`: Хранит поля `id`, `timestamp`, `user_id`, `username`, `action`, `category`, `status`, `ip_address`, `details_json`, `before_state`, `after_state`.
