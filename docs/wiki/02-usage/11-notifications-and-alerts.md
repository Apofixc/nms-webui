# 🔔 Центр уведомлений и оповещений (Notification & Alerts)

---

## 📌 1. Назначение страницы, URL-маршруты и RBAC-права

**Центр уведомлений и оповещений (Notification & Alerts)** — это сквозная подсистема NMS WebUI, обеспечивающая оперативную доставку аварийных сигналов, системных предупреждений и информационных сообщений операторам в реальном времени. Он работает на всех страницах приложения через элементы глобальной шапки (Topbar), всплывающие Toast-уведомления и браузерные Push-оповещения.

* **URL-маршрут**: Доступен сквозным образом на любых страницах платформы через кнопку «Колокольчик» в шапке приложения.
* **Требуемые права доступа (RBAC)**: Доступен всем авторизованным пользователям (`requiresAuth: true`). Операторы получают только те уведомления, на просмотр подсистем которых у них есть соответствующие права (например, события безопасности доставляются обладателям права `system.admin`).

---

## 🖥 2. Подробный функциональный состав

### 2.1. Индикатор шапки (Topbar Bell Badge)
* **Иконка «Колокольчик» (`notifications`)**: Расположена в правой части верхней панели навигации.
* **Бейдж непрочитанных событий**: Красный круг со счетчиком количества необработанных уведомлений.
* **Пульсирующая анимация**: При поступлении критического события (`Critical`) иконка колокольчика начинает пульсировать для привлечения внимания оператора.

---

### 2.2. Выдвижная панель уведомлений (Notification Drawer)
При клике на колокольчик раскрывается боковая панель:

1. **Вкладки фильтрации по категориям**:
   * `Все` — Полный поток сообщений.
   * `Система` — Предупреждения о бэкапах, нагрузке ЦП/RAM, перезапусках служб.
   * `Безопасность` — Ошибки входа, блокировки операторов, изменения прав.
   * `Мониторинг` — Аварии на сетевых устройствах и превышения порогов телеметрии.
   * `Модули` — Сообщения от плагинов.

2. **Список карточек уведомлений**:
   * **Цветовая индикация важности (Severity)**:
     * 🔴 `Critical` — Критическая авария, требующая немедленного вмешательства.
     * 🟡 `Warning` — Предупреждение о потенциальном сбое.
     * 🔵 `Info` — Информационное сообщение.
   * **Содержимое**: Заголовок, краткий текст, штамп времени.
   * **Переход по событию (Interactive Payload)**: Клик по карточке уведомления автоматически перенаправляет оператора на соответствующую страницу (например, к конкретной строке в логах или карточке заблокированного пользователя).

3. **Кнопки групповой обработки**:
   * **«Отметить все как прочитанные» (`done_all`)**: Сбрасывает счетчик непрочитанных событий.
   * **«Очистить прочитанные» (`delete_sweep`)**: Удаляет прочитанные карточки из панели.

---

### 2.3. Всплывающие карточки (Toast Overlays)
* Появляются в нижнем правом углу экрана при поступлении новых событий.
* **Таймер автозакрытия**: Полоса прогресса показывает время до автоматического исчезновения плашки (например, 5 секунд для `Info`, 10 секунд для `Warning`).
* **Критический режим**: Карточки `Critical` не закрываются автоматически и требуют явного клика оператора.

---

### 2.4. Браузерные Push-уведомления и Звук
* **Звуковой сигнал**: Возможность включения/отключения аудио-оповещения при критических авариях.
* **Браузерные Web Push**: Доставка уведомлений, даже если вкладка NMS WebUI свернута.

## 🔄 3. Взаимодействие с остальным приложением

```mermaid
graph TD
    Subsystems[Модули / Логи / Аудит / Мониторинг] -->|Вызов notification_dispatcher.py| Dispatcher[Backend: Dispatcher]
    Dispatcher -->|Сохранение| DB[(SQLite: nms.db - notifications)]
    Dispatcher -->|WebSocket Broadcast| WS[/ws/notifications]
    WS -->|Real-time событие| UI[Frontend: Topbar & Toast System]
    UI -->|REST API PUT/DELETE| API[/api/v1/notifications/*]
    API -->|Обновление статуса| DB
```

### 3.1. Backend REST API
* `GET /api/v1/notifications`: Загрузка списка уведомлений с поддержкой пагинации и фильтрации.
* `PUT /api/v1/notifications/{id}/read`: Отметка конкретного сообщения прочитанным.
* `PUT /api/v1/notifications/read-all`: Отметка всех сообщений прочитанными.
* `DELETE /api/v1/notifications/clear`: Очистка прочитанных сообщений.

### 3.2. WebSockets и Dispatcher (`notification_dispatcher.py`)
* Подсистема `backend/core/notification_dispatcher.py` слушает события со всех компонентов сервера.
* При вызове метода создания уведомления событие мгновенно транслируется по WebSocket-каналу `/ws/notifications` подключенным клиентам WebUI.

### 3.3. База данных `nms.db`
* Таблица `notifications`: Хранит записи (`id`, `user_id`, `title`, `message`, `category`, `severity`, `is_read`, `payload_json`, `created_at`).
