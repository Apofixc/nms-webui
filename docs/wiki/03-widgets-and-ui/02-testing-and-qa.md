# 🧪 Тестирование и Обеспечение Качества (Testing & QA)

---

## 🏛 Стратегия и Пирамида тестирования NMS WebUI

Качество, надежность и безопасность платформы NMS WebUI обеспечиваются двухслойной системой автоматического тестирования:

1. **Backend Unit & Integration Tests (Python / Pytest)**: Покрытие бизнес-логики ядра, авторизации, RBAC-ограничений, работы с SQLite WAL, динамической загрузки плагинов и генерации бэкапов.
2. **Frontend & E2E Browser Automation Tests (Node.js / Chrome DevTools MCP)**: Сквозное автоматизированное тестирование сценариев пользователя в реальном браузере Chromium (авторизация, перемещение виджетов, проверка 4 вкладок, управление пользователями).

## ⚙️ Структура Pytest Сюитов Бэкенда

Все автоматические тесты бэкенда расположены в директориях `tests/` и `tests/backend/`.

### Описание основных файлов тестов:

| Файл теста | Описание и проверяемый функционал |
| :--- | :--- |
| **`tests/test_auth_users_audit.py`** | Тестирование аутентификации, логина, генерации JWT токенов, двухфакторной аутентификации TOTP/2FA, блокировки аккаунтов при неверных входах, завершения сессий и записи журналов аудита. |
| **`tests/test_tuya_integration.py`**<br>`tests/test_tuya_module.py` | Интеграционное тестирование динамического модуля Tuya: загрузка манифеста, регистрация роутов, симуляция ответов драйверов и опрос виджетов. |
| **`tests/test_system_admin_suite.py`** | Проверка работы эндпоинта `/api/system/health`, создания и валидации целостности бэкапов базы данных (`/api/system/backup`, `/api/system/restore`), работы системных логов. |
| **`tests/test_widgets.py`** | Проверка схемы регистрации виджетов бэкенда, генерации JSON-контрактов для `WidgetRenderer` и эндпоинтов телеметрии. |
| **`tests/test_security_edge_cases.py`** | Проверка краевых сценариев безопасности: проверка CIDR белых списков IP (`ip_whitelist`), отзываемость токенов с устаревшим JTI, подмена прав доступа. |
| **`tests/test_log_providers.py`**<br>`tests/test_remote_log_manager.py` | Тестирование локальных провайдеров логов (`backend.log`, `astra.log`) и регистрации удаленных серверов логов (`RemoteHTTPLogProvider`). |
| **`tests/test_e2e_4_tabs.py`**<br>`tests/test_sessions_and_status.py` | Тестирование параллельных сессий пользователя на разных устройствах и алгоритма расчета точного онлайн-статуса `is_online`. |
| **`tests/test_module_i18n.py`** | Проверка динамической загрузки локализаций из папок `locales/` плагинов. |

## 💻 Инструкции по запуску тестов Pytest

Для запуска тестов используйте виртуальное окружение Python `.venv`:

```bash
# 1. Запуск абсолютно всех бэкенд-тестов
.venv/bin/pytest

# 2. Запуск с подробным выводом логов и названий тестов (Verbose)
.venv/bin/pytest -v

# 3. Запуск конкретного тестового файла
.venv/bin/pytest tests/test_auth_users_audit.py

# 4. Запуск конкретного теста по маске имени (-k)
.venv/bin/pytest -k "test_login_success"

# 5. Запуск тестов с остановкой при первой ошибке (-x)
.venv/bin/pytest -x
```

### Конфигурация `pytest.ini`:
Конфигурационный файл `pytest.ini` в корне проекта настраивает путь импортов `pythonpath = .` и игнорирование предупреждений сторонних библиотек.

## 🌐 E2E Сценарии в браузере (Chrome DevTools MCP)

В директории `tests/` содержатся файлы JavaScript для E2E тестирования интерфейса через Chrome DevTools MCP:

```bash
# Запуск сквозного E2E теста пользовательских сценариев
node tests/mcp_chrome_e2e.js

# Запуск полного комплекта E2E тестов администрирования и UI
node tests/mcp_e2e_full_suite.js
```

### Проверяемые E2E сценарии:
- **Авторизация**: Ввод логина/пароля, прохождение смены пароля, проверка JWT.
- **Интерфейс и Виджеты**: Перетаскивание виджетов на дашборде, изменение размеров, скрытие и добавление карточек.
- **Управление пользователями**: Создание нового пользователя, смена роли, блокировка сессий.
- **Системные логи**: Переключение провайдеров логов, фильтрация по уровню `ERROR`/`WARN` и поиск по ключевым словам.
