# Архитектура NMS WebUI

Подробный разбор архитектуры, структурных компонентов, модели данных и взаимодействия сервисов в системе NMS WebUI.

---

## 🏗️ 1. Общая архитектурная схема

Система построена по модульному принципу с четким разделением ответственности (Separation of Concerns):

```
┌───────────────────────────────────────────────────────────────┐
│                    Frontend (Vue 3 + Vite)                    │
│  ┌───────────────┐   ┌─────────────────┐   ┌───────────────┐  │
│  │ Views & Pages │   │ Dynamic Modules │   │ Pinia Stores  │  │
│  └───────┬───────┘   └────────┬────────┘   └───────┬───────┘  │
└──────────┼────────────────────┼────────────────────┼──────────┘
           │ REST API           │ Vue SFC Load       │ WebSockets / SSE
┌──────────▼────────────────────▼────────────────────▼──────────┐
│                      Backend (FastAPI)                        │
│  ┌───────────────┐   ┌─────────────────┐   ┌───────────────┐  │
│  │ Auth & RBAC   │   │ Module Registry │   │  System API   │  │
│  └───────┬───────┘   └────────┬────────┘   └───────┬───────┘  │
└──────────┼────────────────────┼────────────────────┼──────────┘
           │                    │                    │
  ┌───────▼───────┐   ┌────────▼────────┐   ┌───────▼───────┐
  │  SQLite WAL   │   │  Динамические   │   │   MediaMTX    │
  │   (nms.db)    │   │  Модули (Tuya)  │   │ (RTSP Stream) │
  └───────────────┘   └─────────────────┘   └───────────────┘
```

## 🧩 2. Подсистемы и их назначение

### Backend Layer (Python / FastAPI)
- **Точка входа (`backend/main.py`)**: Инициализация приложения FastAPI, подключение middleware, роутеров и автоматический запуск сканирования реестра модулей.
- **Авторизация и безопасность (`backend/core/auth.py`)**: Выдача и валидация JWT-токенов, контроль прав доступа (RBAC), хеширование паролей (Passlib/Bcrypt).
- **База данных (`backend/core/database.py`)**: Работа с SQLite (`backend/data/nms.db`), выполнение миграций, поддержка WAL-режима для высокопроизводительного параллельного чтения и записи.
- **Реестр модулей (`backend/core/plugin/`)**: Динамическое сканирование директории `backend/modules/`, валидация `manifest.json`, регистрация API-маршрутов и обработка жизненного цикла модулей.
- **Шина событий (`backend/core/events.py`)**: Broadcaster для рассылки сообщений через WebSockets и SSE в реальном времени.

### Frontend Layer (Vue 3 + TypeScript + Vite)
- **Кастомная Дизайн-система (`src/style.css`, Material 3 Tokens)**: Единая палитра цветов (Surface, On-Surface, Primary, Shadow Glow, Glassmorphism).
- **Динамический роутинг (`src/core/router.ts`)**: Маршрутизация с проверкой прав доступа и автоматическим встраиванием страниц и меню из динамических модулей.
- **Динамический загрузчик компонентов (`src/core/vueSfcLoader.ts`)**: Модуль, компилирующий `.vue` файлы прямо в браузере клиента на лету без пересборки приложения.
- **Вики и Документация (`src/views/DocumentationView.vue`)**: Встроенный центр справочной документации с автоматическим формированием дерева статей по REST API (`/api/system/docs/wiki/tree`).

## 💾 3. Слой базы данных (SQLite WAL)

База данных располагается по пути `backend/data/nms.db`. Для обеспечения высокой производительности при одновременной работе нескольких модулей SQLite переведена в режим **WAL (Write-Ahead Logging)**.

### Ключевые таблицы ядра:
- `users`: Хранение учетных записей пользователей, паролей, ролей и флагов активности.
- `roles`: Определение системных и пользовательских ролей (например, `admin`, `operator`, `viewer`).
- `active_sessions`: Отслеживание активных JWT-токенов (JTI) для точечного или массового сброса сессий.
- `audit_logs`: Журнал аудита критических операций (кто, когда, с какого IP и какое действие выполнил).
- `module_settings`: Изолированные JSON-настройки модулей.

## 🔁 4. Жизненный цикл запроса (Request Flow)

1. **Запрос от клиента**: Браузер отправляет HTTP-запрос с заголовком `Authorization: Bearer <JWT>`.
2. **Проверка авторизации**: FastAPI Middleware извлекает токен, декодирует его и проверяет `jti` в таблице `active_sessions`.
3. **Контроль доступа (RBAC)**: Зависимость `@require_permission("permission.id")` проверяет права текущей роли пользователя.
4. **Выполнение бизнес-логики**: Хэндлер эндпоинта (в ядре или динамическом модуле) запрашивает данные из БД или внешнего устройства.
5. **Аудит**: Операции изменения данных фиксируются в `audit_logs` через `log_audit_event()`.
6. **Ответ**: Клиент получает структурированный JSON-ответ.

## 🧪 5. Чек-лист проверки архитектурной целостности (QA Checklist)

- [ ] База данных `nms.db` находится в WAL-режиме (наличие файлов `nms.db-wal` и `nms.db-shm` при работе приложения).
- [ ] Все вызовы API требуют валидный Bearer-токен (за исключением белого списка публичных эндпоинтов `/api/system/login` и `/api/system/health`).
- [ ] События аудита создаются корректно при выполнении административных действий.
