# Обзор системы и Назначение NMS WebUI

Добро пожаловать в справочный центр платформы **NMS WebUI** (Network Management System Web UI). 
Данный документ предназначен для первичного ознакомления с назначением системы, её фундаментальной философией и ключевыми архитектурными терминами.

---

## 🎯 1. Назначение и область применения

**NMS WebUI** — это современная модульная событийно-ориентированная веб-платформа для мониторинга сетевой инфраструктуры, IoT-устройств, автоматизации реакций на инциденты и видеостриминга.

### Целевые аудитории и сценарии использования:
1. **Сетевые инженеры и дежурные операторы**:
   * Наблюдение за статусом оборудования на интерактивном Дашборде.
   * Отображение виджетов состояния устройств в реальном времени.
   * Мгновенное получение оповещений об инцидентах через WebSockets/SSE.
2. **Администраторы системы и безопасности**:
   * Управление учетными записями пользователей и ролевой моделью (RBAC).
   * Настройка двухфакторной аутентификации (2FA/MFA).
   * Контроль активных сессий (точечный или массовый сброс скомпрометированных токенов).
   * Непрерывный анализ журнала аудита (Audit Log).
3. **Разработчики динамических модулей**:
   * Создание независимых плагинов (интеграция SNMP, Tuya, MQTT, MediaMTX и др.).
   * Расширение функционала без редактирования и пересборки исходного кода ядра.
4. **QA-инженеры и специалисты по тестированию**:
   * Пошаговая верификация работоспособности сервисов, API и UI с помощью стандартизированных критериев приемки.

## 💡 2. Три ключевых архитектурных принципа

В основе NMS WebUI лежат три фундаментальных принципа разработки:

### Принцип 1: Zero-Boilerplate (Минимум шаблонного кода)
Ядро системы полностью берет на себя рутинные задачи:
* Регистрацию роутов и проксирование запросов.
* Декодирование и валидацию JWT-токенов.
* Контроль прав на уровне декораторов `@require_permission`.
* Подключение к базе данных и управление транзакциями.
* Рассылку сообщений через шину событий `EventBroadcaster`.
* Мультиязычность и локализацию (i18n).

Разработчик модуля пишет только бизнес-логику: манифест `manifest.json`, эндпоинты в `api.py` и Vue-интерфейс в `Index.vue`.

### Принцип 2: 0 Rebuilds Frontend (Динамическая подгрузка компонента на лету)
* **Проблема классических систем**: Добавление страницы или виджета требует запуска сборщика (`npm run build`), остановки веб-сервера и пересборки статического бандла.
* **Решение NMS WebUI**: Клиент подгружает исходный `.vue` файл модуля через REST API `/api/modules/<id>/sfc/<path>` и компилирует его прямо в браузере с помощью `@vue/compiler-sfc` (модуль [`vueSfcLoader.ts`](file:///opt/nms-webui/frontend/src/core/vueSfcLoader.ts)). Новый модуль доступен в UI сразу после копирования папки.

### Принцип 3: Dual Install / Uninstall & Strict Sandboxing
* **Установка и удаление**: Модули устанавливаются простым копированием папки в `backend/modules/<id>/` или запуском встроенного скрипта `install.sh`.
* **Изоляция данных**: Модулю строго запрещено выходить за пределы своей директории хранения данных `backend/data/modules/<id>/`. При удалении модуля скриптом `uninstall.sh` удаляются только его изолированные данные.

## 📖 3. Единый глоссарий терминов

| Термин | Описание |
| :--- | :--- |
| **Core (Ядро)** | Базовый каркас на FastAPI (Backend) и Vue 3 (Frontend), обеспечивающий аутентификацию, системное API, UI-каркас и динамическую загрузку плагинов. |
| **Dynamic Module (Модуль)** | Изолированный плагин расширения, содержащий манифест, backend-логику, роуты, собственные таблицы БД и frontend-компоненты. |
| **Widget (Виджет)** | Карточка/плитка заданной размерности (1x1, 2x2, 4x2), встраиваемая в сетку главного Дашборда. |
| **EventBus & Broadcast** | Шина событий для рассылки сообщений реального времени на клиенты через единый WebSocket-канал `/ws/events`. |
| **RBAC (Role-Based Access Control)** | Матрица контроля доступа «Пользователь → Роль → Разрешения (Permissions)». |
| **Audit Log (Журнал аудита)** | Неизменяемая SQLite-таблица `audit_logs`, фиксирующая чувствительные операции в системе. |
| **SQLite WAL Mode (Write-Ahead Logging)** | Режим работы СУБД, разрешающий параллельное чтение несколькими процессами без блокировки пишущего потока. |
