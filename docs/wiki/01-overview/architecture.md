# Архитектура NMS WebUI

Подробный разбор архитектуры, компонентов, модели данных и взаимодействия сервисов в системе NMS WebUI.

---

## 🏗️ Общая архитектурная схема

Система построенa по модульному принципу с четким разделением ответственности (Separation of Concerns):

```
┌───────────────────────────────────────────────────────────────┐
│                      Frontend (Vue 3 + Vite)                  │
│   ┌───────────────┐   ┌────────────────┐   ┌──────────────┐   │
│   │ Views & Pages │   │ Dynamic Modules│   │ Pinia Stores │   │
│   └───────┬───────┘   └───────┬────────┘   └──────┬───────┘   │
└───────────┼───────────────────┼───────────────────┼───────────┘
            │ REST API          │ Vue Widgets       │ WebSockets / SSE
┌───────────▼───────────────────▼───────────────────▼───────────┐
│                      Backend (FastAPI)                        │
│   ┌───────────────┐   ┌────────────────┐   ┌──────────────┐   │
│   │ Auth & RBAC   │   │ Module Registry│   │ System API   │   │
│   └───────┬───────┘   └───────┬────────┘   └──────┬───────┘   │
└───────────┼───────────────────┼───────────────────┼───────────┘
            │                   │                   │
┌───────────▼───┐       ┌───────▼───────┐   ┌───────▼───────┐
│ SQLite        │       │ Плагины/Модули│   │ MediaMTX      │
│ (nms.db)      │       │ (e.g. Tuya)   │   │ (RTSP Stream) │
└───────────────┘       └───────────────┘   └───────────────┘
```

## 🧩 Подсистемы и их назначение

### 1. Backend (Python / FastAPI)
- **Точка входа (`backend/main.py`)**: Инициализация FastAPI приложения, подключение middleware, роутеров и запуск загрузки модулей.
- **Авторизация и безопасность (`backend/core/auth.py`)**: Выдача и валидация JWT-токенов, контроль прав доступа (RBAC), хеширование паролей (Passlib/Bcrypt).
- **База данных (`backend/core/database.py`)**: Работа с SQLite (`nms.db`), выполнение миграций, пулирование соединений.
- **Реестр модулей (`backend/core/plugin/`)**: Динамическое сканирование директории `modules/`, валидация `manifest.yaml`, регистрация API-маршрутов модулей.

### 2. Frontend (Vue 3 + TypeScript + Vite)
- **Кастомный дизайн (`src/style.css`, Tailwind)**: Использование переменных Material 3 Design Tokens (Surface, On-Surface, Primary, Shadow Glow).
- **Динамический роутинг (`src/core/router.ts`)**: Маршрутизация с проверкой прав доступа и возможностью автоматического встраивания Views из сторонних модулей.
- **База знаний / Вики (`src/views/DocumentationView.vue`)**: Встроенный просмотрщик справочной документации с парсингом Markdown snippets и поиском.

### 3. Слой базы данных (SQLite / nms.db)
Основные таблицы системы:
- `users`: Хранение аккаунтов пользователей, паролей и назначенных ролей.
- `active_sessions`: Отслеживание активных JWT-токенов (JTI) для возможности их централизованного сброса.
- `audit_logs`: Журнал действий пользователей (кто, когда и какое действие выполнил).
- `module_settings`: JSON-настройки плагинов и модулей.

### 4. Видеостриминг (MediaMTX) — *Roadmap / В разработке*
В планах архитектуры предусмотрена интеграция медиасервера MediaMTX (`mediamtx.yml`) для проксирования и трансляции RTSP/HLS/WebRTC видеопотоков с IP-камер во фронтенд NMS WebUI.

## 🔁 Жизненный цикл запроса

1. **Клиент** отправляет HTTP-запрос с заголовком `Authorization: Bearer <JWT>`.
2. **FastAPI Middleware** декодирует токен, проверяет JTI в `active_sessions` и извлекает текущего пользователя (`CurrentUser`).
3. **Зависимость `require_permission("...")`** проверяет наличие необходимых прав у пользователя.
4. **Хэндлер эндпоинта** выполняет бизнес-логику и возвращает JSON-ответ.
5. **Аудит-логгер (`log_audit_event`)** фиксирует выполненную операцию в базе данных.
