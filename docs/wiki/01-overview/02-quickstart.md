## 💻 Системные требования

Перед развертыванием NMS WebUI убедитесь, что рабочее окружение соответствует следующим требованиям:

- **Операционная система**: Linux (Ubuntu 20.04+, Debian 11+, RHEL/Rocky Linux 8+) или POSIX-совместимая среда.
- **Python**: Версия `3.10` или выше (требуется `python3-venv` и `python3-dev`).
- **Node.js**: Версия `18.x` или `20.x` LTS (с пакетным менеджером `npm`).
- **Системные утилиты**: `build-essential`, `lsof`, `procps`, `sqlite3`, `bash`, `curl`.

## ⚡️ Управление платформой через `./run_webui.sh`

В корневом каталоге проекта расположен универсальный управляющий скрипт `run_webui.sh`. Он автоматически обрабатывает создание виртуального окружения Python, установку Node-пакетов, очистку зависших портов и параллельный запуск бэкенда и фронтенда.

### Использование:
```bash
./run_webui.sh <команда> [опции]
```

### Основные команды скрипта:

| Команда | Назначение | Что происходит при запуске |
| :--- | :--- | :--- |
| **`install`** | Полная первичная установка | Установка системных библиотек via `apt-get`, создание `.venv`, установка Python-пакетов (`fastapi`, `uvicorn`, `pydantic`, `httpx`, `celery` и др.) и выполнение `npm install` в `frontend/`. |
| **`dev`** | Обычный режим разработки | Очистка занятых портов, автоматическое создание `.venv` (при отсутствии), запуск FastAPI бэкенда и Vite dev-сервера. |
| **`test`** | Полный тестовый режим | Включает dev-режим + автоматический старт генератора тестовых сигналов (`test_signal_generator.py`) + старт тестовых инстансов Astra. |
| **`stop`** | Полная остановка системы | Завершение процессов по портам (`9000`, `5173`) и по именам (`uvicorn`, `vite`, `test_signal_generator.py`, `vlc`). |
| **`backend`** | Только бэкенд | Запуск только FastAPI сервера (порт 9000). |
| **`frontend`** | Только фронтенд | Запуск только Vite dev-сервера (порт 5173). |
| **`worker`** | Celery Worker | Запуск асинхронного воркера задач Celery (`celery -A main.celery_worker worker`). |
| **`signal [proto]`** | Генератор сигналов | Ручной запуск генератора сигналов. Аргумент `proto`: `all` (по умолчанию), `rtsp`, `mpts`, `hls`. |
| **`reset-root`** | Сброс доступа суперпользователя | Автоматический сброс пароля учётной записи `root` к стандартному значению `admin` via `backend.scripts.reset_root`. |

### Флаги и переменные окружения:

```bash
# Отключение формы авторизации (авто-вход под учётной записью Superuser)
./run_webui.sh dev --no-auth
# или через переменную окружения
NMS_DISABLE_AUTH=1 ./run_webui.sh dev

# Переопределение портов бэкенда и фронтенда
NMS_PORT=9500 NMS_FRONTEND_PORT=3000 ./run_webui.sh dev
```

## ⚙️ Конфигурационные файлы

### 1. Файл переменных окружения `.env`
Файл `.env` располагается в корне проекта и создается автоматически из `.env.example` при первом запуске:

```env
# Параметры сервера и порты
HOST=0.0.0.0
PORT=9000
NMS_FRONTEND_PORT=5173
SECRET_KEY=nms-super-secret-key-change-this-in-production

# База данных
DATABASE_URL=sqlite:///./data/nms.db

# Логирование и режим отладки
LOG_LEVEL=INFO
DEBUG=false

# Отключение авторизации (только для тестовых стендов!)
NMS_DISABLE_AUTH=0
```

### 2. Конфигурация узлов `instances.yaml`
Файл `instances.yaml` управляет подключением внешних серверов мониторинга и узлов NMS:

```yaml
instances:
  - id: local-node-1
    name: "Главный сервер управления (Local)"
    host: "127.0.0.1"
    port: 9000
    enabled: true
    type: "primary"
  - id: edge-node-south
    name: "Южный региональный узел"
    host: "192.168.10.50"
    port: 9000
    enabled: true
    type: "agent"
```

## 🏁 Первичный вход и проверка работоспособности

1. **Запустите систему в dev-режиме**:
   ```bash
   ./run_webui.sh dev
   ```
2. **Откройте браузер** по адресу: `http://localhost:5173` (или IP вашего сервера).
3. **Авторизация по умолчанию**:
   - **Логин**: `root`
   - **Пароль**: `admin`
4. **Первичные шаги администратора**:
   - При первом входе система потребует сменить стандартный пароль `admin` на стойкий пароль (не менее 8 символов, содержащий цифры и спецсимволы).
   - Включите двухфакторную аутентификацию (TOTP) в меню профиля `/user/profile` или в настройках системной безопасности.
5. **Проверка статуса здоровья системы**:
   - Перейдите в браузере на эндпоинт `http://localhost:9000/health` или в интерфейс «Администрирование» -> «Статус системы».
