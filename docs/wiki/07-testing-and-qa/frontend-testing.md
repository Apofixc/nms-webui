# Тестирование Frontend (Vue 3 / E2E)

Для фронтенда **NMS WebUI** предусмотрено два уровня тестирования:
1. **Unit-тесты логики и i18n** — проверка локализации, composables и состояния приложения (`frontend/src/core/__tests__/`).
2. **E2E и интеграционные сценарии** — автоматизация действий через headless-браузер и скрипты Node.js (`tests/mcp_chrome_*.js`).

---

## 🧪 1. Unit-тесты и валидация ресурсов

### Проверка файлов локализации (`i18n.test.ts` / `i18n_check.mjs`)
Скрипты проверяют синхронизацию ключей перевода между `ru.json` и `en.json`:
- Отсутствующие ключи локализации.
- Ошибки форматирования параметров подстановки (например, `{name}`).

```bash
# Запуск проверки локализации
node frontend/src/core/__tests__/i18n_check.mjs
```

---

## 🎭 2. E2E Тестирование в Chrome (MCP / Puppeteer)

В папке `tests/` содержатся сценарии автоматизированного сквозного тестирования:
- `mcp_chrome_e2e.js` — Полный цикл: Авторизация → Просмотр Дашборда → Переключение темы → Выход.
- `mcp_chrome_system_admin_actions.js` — Тестирование вкладки "Администрирование".
- `mcp_chrome_users_actions.js` — Тестирование управления пользователями и ролями.

### Принцип работы E2E скрипта:
1. Запуск экземпляра Chromium / Headless Chrome.
2. Эмуляция ввода данных в формы (логин, пароль, 2FA код).
3. Проверка появления DOM-элементов, сообщений Toast (`ToastNotification.vue`) и диалогов подтверждения (`ConfirmModal.vue`).

---

## 💡 Рекомендации по написанию тестов компонентов

При создании новых Vue-компонентов или виджетов:
- Задавайте уникальные и описательные `id` или `data-testid` атрибуты для ключевых кнопок и инпутов.
- Используйте `useI18n()` для всех пользовательских сообщений, чтобы тесты проверяли локализованный интерфейс.
- Проверяйте работу состояний загрузки и ошибок (Toast notification при сетевом сбое API).
