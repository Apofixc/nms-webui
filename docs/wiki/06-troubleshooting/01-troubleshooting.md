# ❓ FAQ, Поиск решений и Диагностика (Troubleshooting)

---

## 🛠 Матрица редукции ошибок и типовые сценарии

В данном разделе собраны наиболее частые проблемы, возникающие при эксплуатации платформы NMS WebUI, их корневые причины и пошаговые инструкции по устраненю.

---

### 1. Проблемы Базы Данных SQLite (`nms.db`)

#### 🛑 Ошибка: `sqlite3.OperationalError: database is locked`
- **Корневая причина**: Сторонний процесс пытается одновременно записать данные в `nms.db` в обычном режиме (Rollback Journal) вместо режима WAL.
- **Решение**:
  1. Убедитесь, что для базы включен режим WAL:
     ```bash
     sqlite3 data/nms.db "PRAGMA journal_mode=WAL;"
     ```
  2. Проверьте наличией зависших внешних процессов, удерживающих транзакцию:
     ```bash
     lsof data/nms.db
     ```

#### 🛑 Ошибка при восстановлении бэкапа: `DB_INVALID_BACKUP` / `db_no_users_table`
- **Корневая причина**: Загруженный через API файл `.db` поврежден или не содержит таблицы пользователей `users`.
- **Решение**: Проверьте бинарную целостность исходного файла перед загрузкой:
  ```bash
  sqlite3 my_backup.db "PRAGMA integrity_check;"
  sqlite3 my_backup.db "SELECT count(*) FROM users;"
  ```

### 2. Ошибки Авторизации, Сессий и Безопасности

#### 🛑 Ошибка: `429 ACCOUNT_TEMPORARILY_LOCKED` / `ACCOUNT_LOCKED_DURATION`
- **Корневая причина**: Превышено допустимое число неверных вводов пароля (по умолчанию 5 попыток). Аккаунт заблокирован на 30 минут.
- **Решение**:
  - Подождите истечения времени `locked_until` или сбросьте счетчик через команду администратора:
    ```bash
    sqlite3 data/nms.db "UPDATE users SET failed_login_attempts = 0, locked_until = NULL WHERE username = 'target_user';"
    ```

#### 🛑 Ошибка: `403 IP_ACCESS_DENIED`
- **Корневая причина**: IP-адрес вашего компьютера не входит в белые списки `ip_whitelist`, заданные в настройках безопасности.
- **Решение**: Очистите или добавьте свой IP в настройки безопасности через консоль SQLite:
  ```bash
  sqlite3 data/nms.db "UPDATE system_settings SET value = '\"\"' WHERE key = 'security_settings';"
  ```

#### 🛑 Ошибка: `INVALID_2FA_CODE` при вводе 6-значного кода TOTP
- **Корневая причина**: Расхождение системных часов на сервере NMS и смартфоне пользователя более чем на 30 секунд.
- **Решение**: Синхронизируйте точное время сервера через NTP:
  ```bash
  sudo systemctl restart systemd-timesyncd
  date -u
  ```

### 3. Проблемы Загрузки Модулей и Плагинов

#### 🛑 Предупреждение в логах: `Module <id> cannot be enabled: dependency '<dep>' is missing or disabled`
- **Корневая причина**: В манифесте `manifest.yaml` указан обязательный модуль в списке `deps`, который выключен или отсутствует на сервере.
- **Решение**: Проверьте наличие требуемого модуля в каталоге `backend/modules/` и включите его через API `/api/modules/{dep}/toggle`.

#### 🛑 Ошибка: `Несовместимая версия ядра 1.0.0 (требуется min: 2.0.0)`
- **Корневая причина**: Версия ядра бэкенда ниже минимальной версии `min_core_version`, затребованной авторами плагина.
- **Решение**: Обновите ядро NMS WebUI или скорректируйте поле `min_core_version` в `manifest.yaml` плагина.

#### 🛑 Ошибка исполнения: `scripts/install.sh script failed (code 127)`
- **Корневая причина**: Скрипт установки плагина не имеет прав на исполнение или содержит отсутствующие зависимости Linux.
- **Решение**: Назначьте права на исполнение:
  ```bash
  chmod +x backend/modules/<module_id>/scripts/*.sh
  ```

### 4. Ошибки Событий Реального Времени и Стриминга

#### 🛑 Сбой WebSocket: `WebSocket connection to 'ws://...' failed`
- **Корневая причина**: Несовпадение хоста или порта бэкенда, либо отсутствие заголовков Upgrade на обратном прокси Nginx.
- **Решение**: Добавьте в конфигурацию Nginx директивы передачи заголовка Upgrade:
  ```nginx
  proxy_set_header Upgrade $http_upgrade;
  proxy_set_header Connection "Upgrade";
  ```

#### 🛑 Проблемы с событийно-ориентированным потоком WebSockets
- **Корневая причина**: Перевод реального времени с SSE на WebSocket требует поддержки заголовков Upgrade в прокси.
- **Решение**: Убедитесь, что прокси-сервер (Nginx) корректно пробрасывает WebSocket соединения на `/api/events/ws`.

---

### 5. Ошибки Интерфейса и Виджетов

#### 🛑 Виджет показывает плашку: `extension_off - Ошибка компонента виджета`
- **Корневая причина**: Ошибка компиляции или выполнения в пользовательском Vue-компоненте виджета.
- **Решение**: Откройте консоль разработчика в браузере (F12 -> Console) и проверьте точный стектрейс JavaScript ошибки. Выполните сброс компонента кнопкой «Обновить».

## 🚑 Процедура Аварийного Восстановления (Emergency Reset)

Если доступ к учётной записи суперпользователя `root` утерян или пароль забыт, выполните автоматический сброс:

```bash
# Выполнить автоматический сброс пароля root к значению 'admin'
./run_webui.sh reset-root
```

Скрипт обновит сгенерированный хеш пароля для пользователя `root` в базе данных `data/nms.db`. После входа обязательно смените пароль!
