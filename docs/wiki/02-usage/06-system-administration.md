# ⚙️ Системное администрирование платформы

---

## 📌 1. Назначение страницы, URL-маршруты и RBAC-права

Раздел **«Системное администрирование»** предназначен для главных администраторов NMS WebUI. Он содержит инструменты конфигурации системных параметров сервера, резервного копирования и восстановления базы данных, установки и проверки лицензий, а также мониторинга аппаратного состояния сервера и управления фоновыми службами.

* **URL-маршрут**: `/settings/system`
* **Требуемые права доступа (RBAC)**: `system.admin` (Доступен исключительно администраторам системы).

---

## 🖥 2. Подробный функциональный состав

Раздел разделен на четыре ключевые тематические вкладки:

```
[ Настройки платформы ]  [ Резервное копирование ]  [ Лицензирование ]  [ Состояние и Службы ]
```

---

### 2.1. Вкладка «Настройки платформы» (System Settings)
Управление глобальными параметрами функционирования WebUI:

* **Сетевые параметры**:
  * Порт привязки веб-сервера (Host & Port).
  * Настройки SSL/TLS: включение HTTPS, пути к файлам сертификатов (`cert.pem`, `key.pem`).
* **Безопасность сеансов**:
  * Таймаут неактивности (Idle Timeout в минутах).
  * Максимальное количество одновременных сессий на пользователя.
* **Системное логирование**:
  * Выбор глобального уровня детализации логов (`DEBUG`, `INFO`, `WARNING`, `ERROR`).
  * Срок хранения файлов логов (Retention period в днях).

---

### 2.2. Вкладка «Резервное копирование и восстановление» (Backup & Restore)
Управление сохранностью конфигураций и данных:

* **Создание ручной резервной копии (`Create Backup`)**:
  * Мгновенный снимик базы данных `nms.db` и пользовательских настроек.
* **Автоматическое бэкапирование**:
  * Расписание расписания по Cron (например, *«Каждую ночь в 03:00»*).
  * Ограничение максимального количества хранимых копий (Auto-rotation).
* **Таблица резервных копий**:
  * Поля: Имя файла, Размер, Дата создания, Версия системы.
  * Действия: **Скачать** (`download`), **Восстановить** (`settings_backup_restore`), **Удалить** (`delete`).
* **Загрузка внешнего бэкапа**: Модальное окно загрузки файла `.bak` или `.db` с локального компьютера для восстановления системы.

---

### 2.3. Вкладка «Управление лицензиями» (License Management)
Управление правовым статусом и лимитами платформы:

* **Карточка текущей лицензии**:
  * Статус: `Активна`, `Истекает`, `Истекла`.
  * Тип лицензии (Enterprise, Standard, Trial).
  * Лимит устройств и объектов мониторинга (например, *до 5000 устройств*).
  * Срок действия и перечень активированных модулей.
* **Активация новой лицензии**:
  * Форма ввода лицензионного ключа или загрузки файла лицензии `.lic`.
  * Проверка цифровой подписи ключа.

---

### 2.4. Вкладка «Состояние системы и Сервисы» (System Health & Services)
Мониторинг аппаратных ресурсов и фоновых демонов:

* **Аппаратные метрики (Hardware Status)**:
  * Загрузка ЦП (`CPU Usage %`) с динамической диаграммой.
  * Использование оперативной памяти (`RAM Usage` — занято / всего).
  * Занятость дискового пространства (`Disk Storage`).
* **Статус системных служб (Services Table)**:
  * Статусы компонентов: `Backend Python Core`, `Database SQLite`, `Celery Worker`, `WebSocket Gateway`.
* **Управление службами**:
  * Кнопка **«Перезапустить службу»** (`refresh`).
  * Кнопка **«Очистить системный кэш»** (`cleaning_services`).

## 🔄 3. Взаимодействие с остальным приложением

```mermaid
graph TD
    UI[Frontend: SystemAdmin.vue] -->|REST API| API[/api/v1/system/*]
    API -->|Чтение/Запись| DB[(SQLite: nms.db - system_settings)]
    API -->|Файловые операции| FS[Backups / License Files]
    API -->|Системный вызовы OS| OS[Linux OS / Kernel Metrics / ProcFS]
    API -->|Запись критических событий| Audit[SecurityAuditLog]
```

### 3.1. Backend REST API
* `GET/PUT /api/v1/system/settings`: Чтение и обновление системных параметров.
* `GET/POST /api/v1/system/backup`: Получение списка копий и запуск бэкапа.
* `POST /api/v1/system/restore`: Процедура восстановления системы из копии.
* `GET/POST /api/v1/system/license`: Проверка и активация лицензионного ключа.
* `GET /api/v1/system/health`: Запрос аппаратной телеметрии сервера.
* `POST /api/v1/system/services/restart`: Команда перезапуска фонового процесса.

### 3.2. База данных `nms.db`
* Таблица `system_settings`: Хранит ключевые конфигурационные параметры платформы.
* Резервное копирование производит горячий снимки базы `nms.db` с блокировкой записью через WAL-режим (Write-Ahead Logging).

### 3.3. Взаимодействие с операционной системой Linux
* Мониторинг ресурсов читает системные файлы `/proc/stat`, `/proc/meminfo`, `df -h`.
* Управление службами выполняет команды через системные демоны процесса NMS WebUI.

### 3.4. Аудит и Безопасность
* Операции восстановления базы данных, смена лицензий и системных настроек имеют наивысший уровень приоритета в `SecurityAuditLog`.
